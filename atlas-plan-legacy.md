# Atlas plan: Atlas Legacy module

Part of [Moving Atlas Core fully to CSS variables](atlas-plans.md). Status: decided, nothing implemented. Written
2026-11-24, after the WC-3573 spike and a design review of its outcome.

## Why

Atlas Core 5 becomes a thin, neutral fallback: the structure Mendix needs plus minimal styling on semantic tokens, so
an app can put its own design system on top. Everything that only exists to make apps look like Atlas 4 leaves Atlas
Core. It goes to a new module, **Atlas Legacy**. An existing app that upgrades to Atlas Core 5 and wants to keep its
look installs Atlas Legacy.

Atlas Legacy replaces the earlier plan to flip `$exclude-bootstrap` and `$exclude-mxui` in 5.0.0 and delete the files one
major later (phases 3, 4 and 6 of the main plan).

|               | Name                                          |
| ------------- | --------------------------------------------- |
| Mendix module | `Atlas_Legacy`                                |
| Styles        | `packages/atlas/src/themesource/atlas_legacy` |
| Build package | `packages/atlas-legacy`                       |

## Decisions

| #   | Decision                                                                                                                                                                                                                                                                                                      | Why                                                                                                                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Atlas Legacy always runs on top of Atlas Core 5. It never replaces it                                                                                                                                                                                                                                         | It restores a look on top of the thin core. The mandatory parts (reset, scroll container structure) stay in core and are not duplicated                                                  |
| 2   | Legacy is decided by the look rule: whatever only exists to keep the Atlas 4 look. Test for a doubtful case: would a new app on a neutral design system miss it?                                                                                                                                              | An origin rule ("everything from Bootstrap") would keep the Atlas 4 look in core under a new name                                                                                        |
| 3   | Atlas Core keeps minimal neutral styling for the widgets built into Studio Pro. Their Atlas 4 look goes to Atlas Legacy. When core widgets become pluggable, the neutral layer moves to the core widgets module                                                                                               | Without it, a new app on Atlas Core 5 needs Atlas Legacy to be usable                                                                                                                    |
| 4   | The layouts (`Atlas_Default`, `Atlas_TopBar`, `Atlas_SideBar`) stay in Atlas Core with their names. Their structure stays in core, their look moves to Atlas Legacy                                                                                                                                           | Pages reference layouts by name. Moving them means a model migration in every app                                                                                                        |
| 5   | Atlas Legacy owns all the Sass it needs. It never reads Atlas Core's Sass variables, mixins or switches                                                                                                                                                                                                       | Atlas Core 5 removes those, which is exactly when Atlas Legacy has to work                                                                                                               |
| 6   | Copy now, delete at 5.0.0. Atlas Legacy gets copies of the legacy rules slice by slice. Atlas Core 4.x keeps the originals behind its `$exclude-*` switches                                                                                                                                                   | Every slice can be tested against the real Atlas 4 look before 5.0.0 depends on it. Nothing changes for 4.x users                                                                        |
| 7   | Atlas Legacy is not released before 5.0.0. Version 1.0 ships with Atlas Core 5.0.0                                                                                                                                                                                                                            | In 4.x it would duplicate the rules Atlas Core still emits                                                                                                                               |
| 8   | Atlas Legacy replaces the escape hatch. Atlas Core 5.0.0 deletes `core/_legacy/` and the `$exclude-bootstrap` and `$exclude-mxui` switches                                                                                                                                                                    | One way back, not two. Atlas Core is thin from 5.0.0 on                                                                                                                                  |
| 9   | Atlas Core 5 keeps a `$exclude-*` switch for each area that stays in core. Switches whose content moved to Atlas Legacy are removed                                                                                                                                                                           | A design system can switch off core's neutral styling per widget instead of overriding it                                                                                                |
| 10  | Design properties stay in Atlas Core, on semantic tokens. Atlas Legacy carries the Atlas 4 token values and the few design properties that no semantic token can express                                                                                                                                      | A design property is neutral when it styles with a semantic token: "Background: Primary" means whatever the design system calls primary. Existing pages keep all their design properties |
| 11  | Atlas Core owns the semantic token layer, with new neutral names chosen for its future consumers (pluggable widgets, core widgets module). Atlas Legacy maps the 4.x names onto them. A separate tokens module can be split off later                                                                         | The names become a public contract once widgets read them. Splitting a module later is easy, renaming tokens is not                                                                      |
| 12  | Atlas Web Content owns its styling on the semantic tokens, including the Bootstrap rules its building blocks set (`alert-*`, `breadcrumb`, ...)                                                                                                                                                               | New apps start from building blocks. They must not need Atlas Legacy. Same rule as phase 7: a module owns the styling its markup needs                                                   |
| 13  | Glyphicons and the Atlas icon collections stay in Atlas Core. Glyphicons keep `$exclude-glyphicon`                                                                                                                                                                                                            | Studio Pro offers glyphicons in every icon picker. They are a platform feature, not the Atlas look                                                                                       |
| 14  | Structural Bootstrap class names stay supported in Atlas Core, on tokens: grid (`row`, `col-*`, `container`), text alignment and text colors, `hidden-*`, `visible-*`, `pull-*`, `clearfix`, `center-block`. Look classes go to Atlas Legacy: `alert-*`, `label-*`, `badge`, `panel`, `well`, button variants | A grid that silently stops being a grid is worse than a color change. Look classes are what a design system replaces                                                                     |
| 15  | Atlas Legacy keeps Sass themes working, with no end date. A Sass-themed app upgrades by installing Atlas Legacy                                                                                                                                                                                               | Sass themes are the most common existing setup                                                                                                                                           |
| 16  | The WC-3573 spike PR (#366) is closed. Its findings that still hold are below                                                                                                                                                                                                                                 | It built a standalone layout shell, which decision 1 rules out                                                                                                                           |
| 17  | This plan is reviewed on `atlas/themis` and moves to `main` once agreed                                                                                                                                                                                                                                       | The plan owner reviews it where the plan lives                                                                                                                                           |
| 18  | Order of work: copy into Atlas Legacy, then the semantic token layer, then making Atlas Core neutral                                                                                                                                                                                                          | The copy needs nothing else and gives the regression test early. The token names need review time                                                                                        |
| 19  | Regression test: the existing e2e suite in `packages/atlas/e2e`, run in a second mode (Atlas Core with the legacy excluded, plus Atlas Legacy) against the same 4.6.0 baselines as full Atlas Core                                                                                                            | Atlas Legacy is correct when it cannot be told apart from Atlas 4                                                                                                                        |

Follows from the decisions:

-   `_mxui.scss` splits like Bootstrap: structural rules (scroll container, dialog positioning, client defaults) stay in Atlas Core, the look goes to Atlas Legacy.
-   Functional snippets stay in Atlas Core: language selector, feedback, `AppInfo`.
-   Atlas Legacy 1.0 has no switches of its own: install it or not.
-   Atlas Legacy is a styles-only module. Its only possible model content is a `design-properties.json` for the Atlas-only design properties (decision 10).
-   The WC-3573 question "how it works with and without atlas" now means: Atlas Core with its legacy parts excluded, plus Atlas Legacy, looks the same as full Atlas Core.

## Work, in order

1. **Atlas Legacy skeleton and copy.** Module folders and build package. Copy `core/_legacy/bootstrap/` and the look part of `_mxui.scss` verbatim, on Atlas Legacy's own Sass. Test: Atlas Core with `$exclude-bootstrap` and `$exclude-mxui` set to `true`, plus Atlas Legacy, matches full Atlas Core.
2. **e2e legacy mode.** The second mode of decision 19, added to the nightly run.
3. **Semantic token layer.** Names, mapping of the 4.x names (in Atlas Legacy), review.
4. **Atlas Core neutral, per area.** Layouts, then buttons, forms and tables, then the remaining built-in widgets, then pop-ups and dialogs. Each area: its look is copied to Atlas Legacy, core keeps structure and neutral styling on tokens, the e2e legacy mode stays green.
5. **Classify the design properties and the Bootstrap class names** (decisions 10 and 14). Needed before step 4 reaches helpers and widgets.
6. **Atlas Web Content on tokens** (decision 12).
7. **5.0.0.** Atlas Core deletes `core/_legacy/` and the moved switches. Atlas Legacy 1.0 is released. Release notes say which apps need it.

## Findings from the WC-3573 spike that still hold

Tested on 2026-11-10 in a Mendix 11.12.2 project with Atlas Core 4.6.0, Playwright at 1366×768 and 375×812.

-   **The layouts need little from the legacy files.** With `$exclude-bootstrap` and `$exclude-mxui` set to `true`, the regions of all three layout types measured the same as with both files on, as long as these rules exist (in the spike a separate module supplied them; in Atlas Core 5 they belong in core): `box-sizing: border-box`, `html`/`body`/`#content`/`#root` at full height without margin, `.mx-page` at full width and height, `img { vertical-align: middle }`, and a list reset for `.mx-navbar ul.nav` and `.mx-navigationtree ul`. The compiled theme went from 734 KB to 493 KB.
-   **The scroll container structure is CSS in Atlas Core, not in the client.** The React client renders the layout regions but ships no CSS for them (`core/widgets/_scroll-container-react.scss`). Without it the regions do not lay out at all. It is mandatory for Atlas Core 5.
-   **Bootstrap's `.navbar-brand` (float, fixed height, padding) shapes the layouts.** With Bootstrap on, it floats the sidebar logo beside the menu unless a rule resets it. Atlas Core's layouts must not rely on it once Bootstrap leaves.
-   **The layout class sits on the `.mx-page` element itself.** `.mx-page:has(.layout-x)` does not match it; use `.mx-page.layout-x` or both.
-   **A top region's Size does not reach CSS.** The client sets `--sidebar-size` on side regions only. A top bar's height comes from CSS (`--topbar-minimalheight`).
-   **Model dependencies hide where `DESCRIBE` does not show them.** Sidebar toggle buttons carried Atlas Core icons and design properties that only `mxcli bson dump` showed. Check with the raw model when a module must not depend on another.
